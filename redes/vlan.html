VLANs y Listas de Control de Acceso (ACL)

Conceptos previos

Antes de configurar nada, conviene tener claros estos conceptos, ya que se preguntan mucho en exámenes y son la base de todo lo que viene después:

  • VLAN (Virtual LAN) - segmentación lógica de una red física en varios dominios de broadcast independientes. Los equipos de una VLAN no ven el broadcast de otra, aunque estén conectados al mismo switch físico.
  • Puerto access - pertenece a una única VLAN. Se usa para conectar dispositivos finales (PCs, impresoras, servidores, APs). El tráfico que sale/entra por él no lleva ninguna etiqueta.
  • Puerto trunk - transporta el tráfico de varias VLANs a la vez por un mismo cable, añadiendo una etiqueta 802.1Q a cada trama para identificar de qué VLAN es. Se usa entre switches, o entre un switch y un router/firewall.
  • VLAN nativa - en un enlace trunk, es la única VLAN cuyo tráfico viaja sin etiquetar. Por defecto es la VLAN 1. Por seguridad, se recomienda cambiarla a una VLAN que no se use para nada (ni siquiera de gestión), para evitar ataques de VLAN hopping.
  • DTP (Dynamic Trunking Protocol) - protocolo de Cisco que negocia automáticamente si un puerto debe ser access o trunk. En entornos de producción se recomienda desactivarlo con switchport nonegotiate, fijando el modo manualmente por seguridad.
  • Router-on-a-stick - diseño en el que un único router, a través de subinterfaces (una por VLAN), hace de puerta de enlace de todas las VLANs. Válido para redes pequeñas; en redes grandes se sustituye por un switch de capa 3 con SVIs, para no depender de un único enlace físico como cuello de botella.

Pasos para la creación de una VLAN

  1. Primeramente, tenemos que establecer:
    • Las diferentes VLAN
    • Los dispositivos que tendremos
    • El direccionamiento IP
    • La topología de red
  2. Crear VLANs en el Switch:
    • enable
    • configure terminal
    • Creamos VLAN: vlan [número]
    • Ponemos nombre: name [NOMBRE]
    • exit
    • Repetimos con todas las VLANs
  3. Configurar modo acceso:
    • enable
    • configure terminal
    • Entramos en la interfaz que queremos configurar: interface range fastEthernet 0/X-X
    • switchport mode access
    • switchport access vlan [numero_VLAN]
    • Repetimos este paso con todas las VLAN en los diferentes puertos
  4. Configurar modo trunk:
    • En cada uno de los puertos del switch por el que vayan a pasar varias VLAN:
    • enable
    • configure terminal
    • interface fastEthernet 0/X
    • switchport mode trunk
    • (Opcional según dispositivo) switchport trunk encapsulation dot1q
    • (Buena práctica) Limitar las VLANs permitidas: switchport trunk allowed vlan [lista_de_VLANs]
    • (Buena práctica de seguridad) Desactivar la negociación automática: switchport nonegotiate
  5. Configurar Router (Router-on-a-Stick):
    • enable
    • configure terminal
    • Entramos en la interfaz que conecta con el switch: interface fastEthernet 0/X
    • no shutdown
    • exit
  6. Configurar Subinterfaces del Router:
    • Entramos en la subinterfaz: interface fastEthernet 0/X.[número_VLAN]
    • encapsulation dot1Q [número_VLAN]
    • ip address [direccion_IP] [máscara]
    • Repetimos proceso con todas las VLANs
    • Ojo: es el fallo más habitual - si te olvidas del ip address en alguna subinterfaz, esa VLAN se queda sin gateway y ningún equipo de esa red podrá salir de ella (ni recibir IP por DHCP relay, ver aviso más abajo)
  7. Asignar IPs a los diferentes dispositivos:
    • Asignar IP dentro de su VLAN
    • Asignar máscara de red
    • Asignar Gateway (IP de la subinterfaz del router)
  8. Verificación de la configuración:
    • En Switch: show vlan brief
    • En Switch: show interfaces trunk
    • En Router: show ip interface brief
    • Realizar ping entre equipos de la misma VLAN
    • Realizar ping entre VLANs
  9. Guardar configuración:
    • En Switch: copy running-config startup-config
    • En Router: copy running-config startup-config

Aviso - DHCP en un entorno con VLANs: si el servidor DHCP está centralizado en una sola VLAN (por ejemplo, la de Servidores) y las demás VLANs necesitan recibir IP por DHCP, el broadcast DHCPDISCOVER no atraviesa el router por sí solo. Hay que añadir en cada subinterfaz de las VLANs de clientes el comando ip helper-address [IP_del_servidor_DHCP], para que el router reenvíe esas peticiones como unicast hacia el servidor.

Enrutamiento inter-VLAN con switch multicapa (Multilayer Switch)

¿Qué cambia respecto a router-on-a-stick?

En router-on-a-stick, el switch solo trabaja en capa 2 y todo el tráfico entre VLANs tiene que salir por un único enlace físico hacia el router, que es quien hace el routing. En un switch multicapa (o switch de capa 3, "L3 switch"), el propio switch puede enrutar entre VLANs internamente, sin necesitar ningún router ni ningún enlace externo. En Packet Tracer, los modelos 3560 y 3650 son switches multicapa.

La pieza clave es la SVI (Switch Virtual Interface): una interfaz virtual asociada a una VLAN, que actúa como puerta de enlace de esa VLAN, de forma equivalente a como lo hacía cada subinterfaz del router en router-on-a-stick.

Pasos para configurar el enrutamiento inter-VLAN

  1. Crear las VLANs igual que siempre:
    • vlan [número]
    • name [NOMBRE]
  2. Activar el enrutamiento en el switch (viene desactivado por defecto):
    • configure terminal
    • ip routing
  3. Crear una SVI por cada VLAN, con su IP de gateway:
    • interface vlan [número_VLAN]
    • ip address [dirección_IP] [máscara]
    • no shutdown
    • Repetir con todas las VLANs
  4. Configurar los puertos de acceso hacia los dispositivos finales igual que en un switch normal:
    • interface range fastEthernet 0/X-X
    • switchport mode access
    • switchport access vlan [numero_VLAN]
  5. Si el switch multicapa se conecta a otro switch de acceso (para repartir las VLANs entre varios switches físicos), ese enlace sigue siendo un trunk normal:
    • interface fastEthernet 0/X
    • switchport mode trunk
    • switchport trunk allowed vlan [lista_de_VLANs]
  6. Si alguno de los puertos del switch multicapa va a conectarse directamente a un router o a otro dispositivo de capa 3 sin hacer trunking (por ejemplo, para salir a Internet), ese puerto puede convertirse en un puerto enrutado (routed port), dejando de comportarse como puerto de switch:
    • interface gigabitEthernet 0/X
    • no switchport
    • ip address [dirección_IP] [máscara]

Ejemplo rápido

Para las VLANs 10 (Servidores) y 99 (Invitados):

  • ip routing
  • interface vlan 10
  •   ip address 192.168.10.1 255.255.255.0
  •   no shutdown
  • interface vlan 99
  •   ip address 192.168.99.1 255.255.255.0
  •   no shutdown

Verificación

  • show vlan brief - VLANs y puertos asignados
  • show ip interface brief - estado de cada SVI (deben salir up/up)
  • show ip route - las SVIs activas aparecen como redes conectadas directamente, sin necesidad de ningún protocolo de enrutamiento

Errores comunes

  • Olvidar el comando ip routing - sin él, el switch multicapa se comporta como un switch normal de capa 2 y las VLANs no se comunican entre sí aunque las SVIs tengan IP
  • Olvidar el no shutdown en la SVI - las SVIs, igual que cualquier interfaz, nacen administrativamente apagadas
  • Confundir interface vlan [número] (la SVI, virtual) con interface fastEthernet 0/X (un puerto físico) - son conceptos distintos aunque ambos puedan llevar ip address
  • La SVI de una VLAN no se activa si esa VLAN no tiene ningún puerto físico activo (up) asignado a ella; en algunas versiones de IOS puede quedar en estado down/down hasta que haya al menos un puerto en esa VLAN funcionando

Nota: este es exactamente el diseño que se usa en la inmensa mayoría de redes empresariales reales. Se explica con más detalle, y se compara con router-on-a-stick, en la conversación donde se generó este apartado del manual.

Listas de Control de Acceso (ACL)

¿Qué es una ACL?

Una ACL es un conjunto de reglas (sentencias permit / deny) que se evalúan de arriba a abajo, en orden, sobre el tráfico que entra o sale de una interfaz. En cuanto una sentencia coincide con el tráfico, se aplica esa acción y se deja de evaluar el resto de la lista. Al final de toda ACL existe un deny ip any any implícito que no aparece escrito, pero que siempre está ahí.

Tipos de ACL

  • Estándar (rango 1-99 y 1300-1999) - solo puede filtrar por IP de origen. Al ser tan poco específica, se recomienda colocarla lo más cerca posible del destino, para no bloquear por error tráfico legítimo hacia otros destinos distintos.
  • Extendida (rango 100-199 y 2000-2699) - puede filtrar por IP origen, IP destino, protocolo (tcp, udp, icmp...) y puerto. Al ser más precisa, se recomienda colocarla lo más cerca posible del origen, para descartar el tráfico no deseado cuanto antes y no malgastar ancho de banda de la red.
  • Nombrada (named ACL) - en vez de un número, se le da un nombre descriptivo. Su gran ventaja es que permite insertar, eliminar o modificar líneas concretas sin tener que borrar y recrear toda la lista (las numeradas clásicas no lo permiten con facilidad).

La máscara wildcard

Las ACL no usan la máscara de subred normal, sino su inversa, llamada máscara wildcard. Un 0 significa "este bit debe coincidir exactamente"; un 1 significa "este bit no importa, puede ser cualquier valor".

  • Máscara de subred 255.255.255.0 → wildcard equivalente 0.0.0.255
  • Máscara de subred 255.255.0.0 → wildcard equivalente 0.0.255.255
  • Para referirse a un único host: wildcard 0.0.0.0, o directamente la palabra clave host [IP]
  • Para referirse a cualquier IP: wildcard 255.255.255.255, o directamente la palabra clave any

Truco rápido: la wildcard se calcula restando la máscara de subred a 255.255.255.255. Por ejemplo, para /24 (255.255.255.0): 255.255.255.255 - 255.255.255.0 = 0.0.0.255.

Reglas de oro

  1. El orden importa: se evalúa de arriba a abajo, y gana la primera coincidencia.
  2. Existe un deny implícito al final de toda ACL. Si no añades tu propio permit final, se bloqueará absolutamente todo el tráfico de esa interfaz (incluyendo DHCP, ARP resuelto por el router, etc.).
  3. Solo se puede aplicar una ACL por protocolo, por dirección (in/out) y por interfaz. Es decir, una interfaz puede tener una ACL de entrada y otra distinta de salida, pero no dos de entrada a la vez.
  4. Las extendidas se colocan cerca del origen; las estándar cerca del destino.

Sintaxis básica

  • ACL estándar: access-list [1-99] [permit|deny] [origen] [wildcard_origen]
  • ACL extendida: access-list [100-199] [permit|deny] [protocolo] [origen] [wildcard_origen] [destino] [wildcard_destino] [operador puerto]
  • ACL nombrada: ip access-list extended [NOMBRE], y dentro se escriben las líneas permit/deny sin repetir access-list delante

Aplicar la ACL a una interfaz

  • interface [interfaz]
  • ip access-group [número o nombre] [in|out]

in filtra el tráfico que entra al router por esa interfaz (viniendo desde esa red); out filtra el tráfico que sale del router hacia esa interfaz.

Ejemplo práctico: bloquear una VLAN de invitados hacia la VLAN de servidores

Supongamos la VLAN 99 (Invitados, red 192.168.99.0/24) y la VLAN 10 (Servidores, red 192.168.10.0/24). Queremos que Invitados no pueda llegar a Servidores, pero sí pueda salir a cualquier otro sitio (por ejemplo, Internet):

  • access-list 100 deny ip 192.168.99.0 0.0.0.255 192.168.10.0 0.0.0.255
  • access-list 100 permit ip any any
  • interface gi0/0.99
  • ip access-group 100 in

La misma ACL, en versión nombrada

  • ip access-list extended BLOQUEO_INVITADOS
  •   deny ip 192.168.99.0 0.0.0.255 192.168.10.0 0.0.0.255
  •   permit ip any any
  • interface gi0/0.99
  • ip access-group BLOQUEO_INVITADOS in

Filtrado por protocolo y puerto (ejemplo real)

Por ejemplo, para bloquear el acceso por Telnet (puerto 23) a un servidor concreto, pero permitir el resto de tráfico:

  • access-list 110 deny tcp any host 192.168.10.5 eq 23
  • access-list 110 permit ip any any

Verificación

  • show access-lists - muestra todas las ACL configuradas y, en Packet Tracer/IOS reciente, cuántas veces ha coincidido cada línea (contador de matches)
  • show ip interface [interfaz] - muestra si esa interfaz tiene una ACL aplicada y en qué sentido (in/out)
  • show running-config - para revisar la configuración completa aplicada

Errores comunes con ACL

  • Olvidar el permit ip any any final, bloqueando sin querer toda la VLAN (el error más grave y más habitual)
  • Colocar una ACL extendida cerca del destino en vez de cerca del origen (funciona, pero es ineficiente y no es buena práctica)
  • Confundir la máscara wildcard con la máscara de subred normal (son inversas una de la otra)
  • Aplicar la ACL en la dirección incorrecta (in en vez de out, o viceversa)
  • Añadir una línea nueva a una ACL numerada ya creada: por defecto se añade al final de la lista, lo que puede no ser donde realmente la necesitas. Para insertar en medio, hace falta usar números de secuencia (con ACL nombradas) o recrear la lista entera

Contexto real: las ACL de un router son stateless (no recuerdan el estado de las conexiones) y constituyen una primera capa de defensa muy básica. En entornos profesionales serios, esta función se complementa o sustituye por un firewall dedicado (Fortinet, pfSense, Cisco ASA/Firepower...), que sí es stateful y ofrece muchas más posibilidades de inspección del tráfico.
