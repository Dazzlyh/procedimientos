Docker

Teoría

Docker es una plataforma para crear, distribuir y ejecutar aplicaciones dentro de contenedores: entornos aislados y ligeros que empaquetan una aplicación con todo lo que necesita para funcionar (librerías, dependencias, configuración). A diferencia de una máquina virtual, el contenedor comparte el kernel del sistema anfitrión, por lo que arranca rápido y consume pocos recursos.

Conceptos clave:

  • Imagen - plantilla de solo lectura con la que se crean los contenedores
  • Contenedor - instancia en ejecución de una imagen
  • Dockerfile - fichero de texto con las instrucciones para construir una imagen
  • Volumen - mecanismo para guardar datos de forma persistente fuera del contenedor
  • Registro (registry) - repositorio de imágenes (p. ej. Docker Hub)

Tags de las imágenes

Una imagen se identifica como nombre:tag (por ejemplo ubuntu:22.04). El tag indica la versión o variante de la imagen. Si no se indica ninguno, Docker asume :latest por defecto.

Aislamiento entre tags de una misma imagen

Cada contenedor es independiente, incluso si parten de la misma imagen con distinto tag. Se pueden tener varios contenedores corriendo a la vez (por ejemplo nginx:1.24 y nginx:1.25) sin que se interfieran entre sí: cada uno tiene su propio sistema de ficheros, procesos y red. Para distinguirlos cómodamente conviene darles un nombre con --name.

Volúmenes: para qué sirven

El sistema de ficheros de un contenedor es efímero: cuando eliminas el contenedor, todo lo que había dentro desaparece. Los volúmenes resuelven ese problema permitiendo que los datos vivan fuera del contenedor, en el anfitrión. Sus usos principales son:

  • Persistencia - guardar datos que deben sobrevivir al ciclo de vida del contenedor (bases de datos, subidas de usuarios, logs)
  • Compartir datos - que varios contenedores accedan a la misma información
  • Desarrollo en caliente - montar la carpeta de código del anfitrión dentro del contenedor para que los cambios se reflejen sin reconstruir la imagen
  • Copias de seguridad y migración - resulta más fácil respaldar un volumen que un contenedor entero

Bind mount vs volumen gestionado

Docker ofrece dos formas principales de montar datos, ambas se declaran con -v:

  • Bind mount - se enlaza una ruta concreta del anfitrión con una ruta del contenedor (-v /ruta/anfitrion:/ruta/contenedor). Los cambios en cualquiera de los dos lados se ven al instante. Es lo típico para desarrollo, cuando quieres editar el código en tu editor y que el contenedor lo vea.
  • Volumen gestionado - se le da un nombre y Docker gestiona dónde se guarda (-v nombre_volumen:/ruta/contenedor). Es la opción recomendada para datos de aplicaciones y bases de datos, porque es más portable y Docker se encarga de su ubicación.

Modificación del código sin reconstruir

Durante el desarrollo, reconstruir la imagen con docker build cada vez que se cambia una línea sería lento. La solución habitual es montar la carpeta del código como bind mount: el contenedor lee los archivos directamente del anfitrión, por lo que al editar el código en local, el contenedor ve el cambio inmediatamente (a veces hará falta reiniciar el proceso interno, según la tecnología).

Comandos básicos

docker run

docker run [opciones] [imagen] [argumentos] - crea y arranca un contenedor a partir de una imagen. Si la imagen no está en local, la descarga primero.

Opciones más habituales:

  • -d (detached) ejecuta el contenedor en segundo plano, sin bloquear la terminal
  • -i (interactive) mantiene la entrada estándar (STDIN) abierta
  • -t (tty) asigna un pseudo-terminal. Se suele combinar como -it para entrar en una shell
  • -a (attach) adjunta STDIN, STDOUT o STDERR al contenedor (p. ej. -a stdout)
  • --name [nombre] asigna un nombre personalizado al contenedor (si no, Docker pone uno aleatorio)
  • -h [hostname] establece el hostname interno del contenedor
  • -u [usuario] ejecuta el proceso como el usuario indicado en lugar de root
  • -e [VARIABLE=valor] define una variable de entorno dentro del contenedor
  • --rm elimina el contenedor automáticamente al pararlo
  • --restart [política] define cuándo reiniciar el contenedor: no (por defecto), on-failure, always, unless-stopped
  • --entrypoint [comando] sobreescribe el ENTRYPOINT definido en la imagen
  • -v monta un volumen o un bind mount (ver sección de volúmenes)
  • --volumes-from [contenedor] reutiliza los volúmenes ya montados por otro contenedor
  • -p [host]:[contenedor] publica un puerto concreto (ver subsección de puertos)
  • -P publica todos los puertos declarados con EXPOSE, en puertos aleatorios del anfitrión
  • --expose [puerto] expone un puerto adicional sin publicarlo (documentativo, útil con --link)
  • --link [contenedor]:[alias] enlaza con otro contenedor (ver sección avanzada, en desuso)

Publicación de puertos

Para que un servicio del contenedor sea accesible desde el anfitrión hay que publicar puertos:

  • -p [host]:[contenedor] mapea un puerto concreto. Ejemplo: -p 8080:80 hace que el 80 del contenedor sea accesible desde el 8080 del anfitrión
  • -p [contenedor] si solo se indica un puerto, se publica en un puerto aleatorio del anfitrión
  • -P publica todos los puertos declarados con EXPOSE en la imagen, cada uno en un puerto aleatorio del anfitrión
  • --expose [puerto] NO publica el puerto, solo lo declara. Sirve para que otros contenedores lo vean (típico con --link)

docker port

docker port [contenedor] - muestra a qué puertos del anfitrión están mapeados los puertos del contenedor. Útil sobre todo cuando se han asignado aleatoriamente con -P.

docker port [contenedor] [puerto] - muestra el mapeo de un puerto concreto

docker pull

docker pull [imagen]:[tag] - descarga una imagen desde un registro (Docker Hub por defecto) sin crear el contenedor

docker tag

docker tag [imagen_origen] [imagen_destino]:[tag] - crea un alias (una nueva etiqueta) para una imagen existente. No duplica la imagen, solo le añade otro nombre. Se usa sobre todo antes de un push, para renombrar la imagen con tu usuario del registro.

  • Ejemplo: docker tag miapp:latest usuario/miapp:1.0

docker push

docker push [usuario/imagen]:[tag] - sube una imagen a un registro. Requiere haber iniciado sesión (docker login) y que la imagen esté etiquetada con tu usuario (normalmente con docker tag previo)

docker images

docker images - lista todas las imágenes descargadas en local (nombre, tag, ID, tamaño)

docker ps

docker ps - lista los contenedores en ejecución

  • -a muestra todos los contenedores, también los parados
  • -q muestra solo los IDs (útil para combinar con otros comandos)
  • -s muestra el tamaño de cada contenedor
  • -l muestra el último contenedor creado
  • -n [número] muestra los últimos N contenedores
  • -f [filtro] filtra por condición (p. ej. -f status=exited)

docker stop / start / restart

docker stop [contenedor] - detiene un contenedor en ejecución (lo apaga de forma ordenada)

docker start [contenedor] - vuelve a arrancar un contenedor que estaba parado

docker restart [contenedor] - reinicia un contenedor (equivale a stop + start)

docker rm

docker rm [contenedor] - elimina un contenedor parado. Si está en ejecución (UP), dará error salvo que se fuerce

docker rm -f [contenedor] - fuerza la eliminación aunque el contenedor esté en ejecución

docker rmi

docker rmi [imagen] - elimina una imagen de local (no un contenedor). No se puede borrar si hay contenedores que la usan

Comandos intermedios

docker exec

docker exec [opciones] [contenedor] [comando] - ejecuta un comando dentro de un contenedor que ya está corriendo

  • -i (interactive) mantiene la entrada estándar abierta
  • -t (tty) asigna una terminal
  • -it [contenedor] sh combinación habitual para abrir una shell interactiva dentro del contenedor (también bash si la imagen lo incluye)

docker logs

docker logs [opciones] [contenedor] - muestra la salida (logs) generada por un contenedor

  • -f (follow) muestra los logs en tiempo real según se generan
  • -t añade marca de tiempo (timestamp) a cada línea
  • --tail [número] muestra solo las últimas N líneas
  • --since [tiempo] muestra los logs a partir de un momento dado (p. ej. 10m, una fecha)
  • --until [tiempo] muestra los logs hasta un momento dado
  • --details muestra detalles adicionales de cada entrada

docker inspect

docker inspect [contenedor|imagen] - devuelve un JSON con toda la información del contenedor o imagen: configuración, red, volúmenes montados, variables de entorno, etc.

  • -f "[plantilla]" filtra la salida usando una plantilla Go, para extraer solo lo que interesa
  • docker inspect -f '{{.Mounts}}' [contenedor] - muestra únicamente los volúmenes y bind mounts del contenedor
  • docker inspect -f '{{.NetworkSettings.IPAddress}}' [contenedor] - extrae solo la IP interna del contenedor
  • docker inspect -f '{{.State.Status}}' [contenedor] - muestra solo el estado (running, exited...)

docker rename

docker rename [nombre_actual] [nombre_nuevo] - cambia el nombre de un contenedor existente

docker search

docker search [término] - busca imágenes en Docker Hub desde la terminal

  • --limit [número] limita el número de resultados mostrados
  • -f stars=[número] filtra por número mínimo de estrellas
  • -f is-official=true muestra solo imágenes oficiales

docker stats

docker stats - muestra en tiempo real el consumo de recursos (CPU, memoria, red, disco) de los contenedores activos

docker info

docker info - muestra información general del sistema Docker: número de contenedores e imágenes, versión, driver de almacenamiento, recursos, etc.

docker save / load

docker save -o [archivo.tar] [imagen] - exporta una imagen a un archivo .tar para guardarla o transportarla sin un registro

docker load -i [archivo.tar] - importa una imagen desde un archivo .tar generado con save

Eliminar varios contenedores con filtros

docker rm $(docker ps -aq -f [filtro]) - elimina de golpe varios contenedores filtrándolos primero, sin tener que escribir cada uno. El comando interno (entre $()) devuelve los IDs y docker rm los borra.

  • docker rm $(docker ps -aq) - elimina todos los contenedores parados
  • docker rm -f $(docker ps -aq) - elimina todos los contenedores, también los que estén en ejecución
  • docker rm $(docker ps -aq -f status=exited) - elimina solo los que han terminado (exited)
Filtros habituales con -f: status=exited, status=running, name=[texto], ancestor=[imagen].

Comandos avanzados

Estructura típica de un proyecto con Docker

Para construir una imagen propia, lo normal es tener una carpeta de proyecto con esta estructura mínima:

miapp/
  Dockerfile
  .dockerignore
  package.json   (en Node.js; requirements.txt en Python, etc.)
  index.js   (código principal)
  src/
  public/

  • Dockerfile - instrucciones para construir la imagen
  • .dockerignore - archivos y carpetas que no queremos que Docker envíe al construir la imagen (p. ej. node_modules, .git). Es equivalente al .gitignore
  • Código de la app - index.js, dependencias declaradas (package.json) y cualquier carpeta de código o recursos

Desde esa carpeta se ejecuta docker build, y ese directorio se convierte en el contexto de construcción que Docker envía al motor.

Dockerfile y su estructura

Un Dockerfile es un fichero de texto (sin extensión, llamado literalmente Dockerfile) con las instrucciones para construir una imagen propia, paso a paso. Instrucciones principales:

  • FROM [imagen]:[tag] imagen base de la que partimos. Siempre es la primera instrucción
  • MAINTAINER [autor] indica el autor/mantenedor de la imagen. Está en desuso, hoy se usa LABEL maintainer="..."
  • WORKDIR [ruta] establece el directorio de trabajo dentro de la imagen para las instrucciones siguientes
  • COPY [origen] [destino] copia archivos del contexto de construcción a la imagen
  • ADD [origen] [destino] como COPY pero además admite URLs y descomprime archivos .tar automáticamente
  • RUN [comando] ejecuta un comando durante la construcción (instalar paquetes, compilar, etc.). Cada RUN genera una capa
  • ENV [VARIABLE=valor] define una variable de entorno persistente en la imagen
  • USER [usuario] establece el usuario con el que se ejecutarán las instrucciones siguientes y el proceso del contenedor
  • EXPOSE [puerto] documenta el puerto que usará el contenedor (no lo publica en el anfitrión)
  • VOLUME ["/ruta"] declara un punto de montaje como volumen: Docker creará un volumen anónimo ahí si al arrancar no se especifica uno
  • CMD ["comando", "arg"] comando por defecto al arrancar el contenedor. Se puede sobreescribir al hacer docker run
  • ENTRYPOINT ["comando", "arg"] comando fijo al arrancar. No se sobreescribe con argumentos de run; para cambiarlo hay que usar --entrypoint
  • ONBUILD [instrucción] instrucción que se ejecutará automáticamente cuando otra imagen use esta como base (FROM). Útil para imágenes plantilla

docker build

docker build -t [nombre]:[tag] [ruta] - construye una imagen a partir de un Dockerfile.

  • -t [nombre]:[tag] asigna nombre y tag a la imagen resultante
  • La ruta suele ser . (el directorio actual, donde está el Dockerfile). Ese directorio es el "contexto" que se envía a Docker
  • -f [archivo] indica un Dockerfile con otro nombre o ubicación
  • --no-cache ignora la caché de capas y reconstruye todo desde cero. Útil cuando una capa cacheada no está reflejando cambios (por ejemplo, para forzar que un RUN apt update se vuelva a ejecutar)

Volúmenes en la práctica

(Ver la sección de Teoría para el concepto de volumen, bind mount y volumen gestionado.)

Bind mount - montar una carpeta del anfitrión:

  • docker run -v [ruta_local]:[ruta_contenedor] [imagen] - el contenedor ve la carpeta del anfitrión en la ruta indicada. Los cambios se reflejan en ambos lados en tiempo real. Es lo típico para desarrollar y ver los cambios de código sin reconstruir
  • docker run -v [ruta_local]:[ruta_contenedor]:ro [imagen] - añade :ro para montar en solo lectura

Volumen gestionado - Docker lo administra:

  • docker run -v [nombre_volumen]:[ruta_contenedor] [imagen] - si el volumen no existe, Docker lo crea automáticamente. Es la opción recomendada para datos de aplicaciones (bases de datos, etc.)
  • docker volume ls - lista los volúmenes gestionados
  • docker volume create [nombre] - crea un volumen con nombre de forma explícita
  • docker volume rm [nombre] - elimina un volumen
  • docker volume inspect [nombre] - muestra detalles del volumen (incluyendo la ruta real donde Docker lo guarda)

Volúmenes desde el Dockerfile - con la instrucción VOLUME ["/ruta"]. Al arrancar el contenedor, si no se indica un volumen concreto con -v, Docker crea un volumen anónimo para esa ruta.

--volumes-from - reutilizar volúmenes de otro contenedor:

  • docker run --volumes-from [otro_contenedor] [imagen] - el nuevo contenedor monta los mismos volúmenes que ya tiene el otro. Muy útil para tener un "contenedor de datos" que sirve de almacén compartido a varios contenedores

Inspeccionar los volúmenes de un contenedor:

  • docker inspect -f '{{.Mounts}}' [contenedor] - muestra todos los puntos de montaje del contenedor: tipo (bind o volume), origen en el anfitrión y destino en el contenedor

Enlazar contenedores con --link

docker run --link [contenedor_destino]:[alias] [imagen] - permite que el nuevo contenedor se conecte a otro por nombre, sin necesidad de conocer su IP. Docker añade una entrada en el /etc/hosts del contenedor con el alias indicado y expone las variables de entorno del contenedor enlazado.

  • Ejemplo: docker run --link mi_bbdd:db -d miapp hace que dentro de miapp podamos acceder a la base de datos usando el nombre db

Nota: --link está considerado obsoleto (legacy). Actualmente lo recomendable es crear una red propia con docker network create y conectar los contenedores a ella; se resuelven por nombre igualmente. Aun así, se sigue viendo en muchos cursos y documentación.
